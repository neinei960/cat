# 护理报告手机端独立表单设计

## 背景

当前护理报告编辑依赖在缩小后的报告底图上点击字段、勾选框和备注热点，再通过底部单字段编辑器修改。报告原图为固定宽高模板，缩放到手机后点击区域小、定位困难，用户需要在图片和编辑器之间反复切换。

本次调整将图片从“编辑器”改为“只读展示结果”。用户先在适合手机操作的独立表单中填写数据，再按需打开报告预览，最终仍由现有后端生成固定模板图片。

## 目标

- 所有可编辑字段都在手机表单中直接可见或通过明确的折叠分组访问。
- 用户不需要点击报告图片完成任何编辑操作。
- 报告预览默认收起，避免占用填写空间。
- 表单数据实时写入现有 `OrderCareReportDraft`，预览和提交使用同一份数据。
- 保持现有后端接口和报告图片生成协议不变。

## 非目标

- 不修改护理报告图片模板、坐标或字体。
- 不新增护理报告字段。
- 不修改订单、猫咪档案或护理历史的数据模型。
- 不引入新的前端组件库或表单框架。

## 页面结构

### 顶部区域

- 保留标题、关闭按钮和多猫订单的猫咪切换。
- 单猫订单直接进入填写；多猫订单先选择猫咪，再进入该猫咪的表单。
- 标题下说明改为“填写护理信息后生成报告”。

### 照片与基本信息

使用一个不嵌套卡片的表单区展示：

- 护理照片：显示圆形缩略图和“上传/更换照片”按钮，继续使用现有裁剪上传流程。
- 宝贝名字、品种、年龄、护理内容、体重：标准输入框。
- 性别：`GG` / `MM` 分段选择。
- 护理日期、建议下次护理日期：日期选择器。
- 体型：太瘦、偏瘦、标准、偏胖、肥胖单选。

字段直接绑定 `draft`，无需单独保存。

### 检查记录

皮肤、被毛、指甲、眼睛及脸部、耳朵、口腔、肛门及周围分别作为折叠分组：

- 分组标题显示名称和已选数量。
- 默认展开第一个分组；同一时间只展开一个分组，减少页面长度。
- 选项使用可换行的复选按钮，支持多选。
- 备注输入框放在该分组选项下方，保持选填。
- 切换分组不会清除已填写内容。

### 底部操作

底部固定操作栏保留两个主操作：

- `预览报告`：打开只读预览层，展示当前 `draft` 映射后的报告，不允许在图片上编辑。预览默认关闭。
- `生成报告`：先校验表单，再调用现有生成接口。

关闭操作继续放在页面头部，避免底部三个同权重按钮挤压手机宽度。

## 组件边界

### `OrderCareReportModal.vue`

负责：

- 猫咪选择和当前 `draft` 生命周期。
- 独立表单渲染、分组展开状态和字段更新。
- 上传裁剪、校验、生成、保存和重新填写流程。
- 控制只读预览层的展开和关闭。

移除对图片热点编辑器的依赖，包括 `activeEditor`、`editorDescriptor`、编辑底栏和 `edit-target` 交互。

### `OrderCareReportStage.vue`

继续负责把 `draft` 映射到报告模板，用于只读预览。组件保留现有绘制逻辑，但在护理报告弹窗中不再启用 `editable`。

本次不强制删除组件内部的通用热点能力，以免扩大变更范围；没有消费者后可在后续独立清理。

### `order-care-report.ts`

继续作为字段定义、选项定义、默认值和提交 payload 的唯一数据来源。表单复用 `orderCareReportBodyShapeOptions` 与 `orderCareReportSectionDefinitions`，不在页面复制业务选项。

## 数据流

1. 选择猫咪后调用 `buildOrderCareReportDraft` 初始化表单。
2. 输入框、日期、分段选择和复选项直接更新当前 `draft`。
3. 打开预览时，将同一个 `draft` 传给只读 `OrderCareReportStage`。
4. 点击生成时，`validateDraft` 校验必填项。
5. 校验通过后，`buildOrderCareReportPayload` 生成现有请求体并调用后端。
6. 后端返回最终图片 URL，进入现有保存图片流程。

## 校验与异常处理

- 必填项保持现有口径：照片、护理内容、体重、护理日期、下次护理日期、体型。
- 每个必填字段对应稳定的表单锚点。
- 校验失败时展开包含该字段的区域，滚动到第一个缺失字段并显示现有 Toast。
- 上传和生成期间禁用对应按钮，避免重复请求。
- 上传失败、生成失败和保存失败继续复用现有反馈，不清空已填数据。
- 切换猫咪时为目标猫咪重新初始化 `draft`，避免不同猫咪的数据串写。

## 响应式与可用性

- 表单按手机单列布局，不使用横向滚动。
- 输入框、日期选择器和选项按钮的有效点击高度不低于 44px。
- 复选按钮允许文本换行，长标签不溢出。
- 底部固定操作栏预留安全区，键盘打开时不遮挡当前输入框。
- 报告预览使用完整宽度缩放，关闭后回到原填写位置。

## 测试与验收

### 自动化测试

- 源码/组件测试确认弹窗不再启用报告热点编辑。
- 确认所有基本字段、体型和七个检查分组都绑定到 `draft`。
- 确认检查项复用共享定义，并支持展开、勾选和备注输入。
- 确认预览默认关闭，打开后 `OrderCareReportStage` 为只读。
- 确认现有 payload 构建与后端生成测试继续通过。

### 浏览器验收

- 使用手机宽度打开订单详情并进入护理报告。
- 验证单猫、多猫切换、照片上传入口、所有字段和折叠分组可操作。
- 验证页面没有横向溢出，底部操作栏不遮挡最后一个分组。
- 验证预览默认收起，打开后内容与表单一致且不能点击编辑。
- 验证生成报告成功，并能进入现有保存图片流程。

## 发布范围

本次预计只修改前端护理报告弹窗及其前端回归测试。代码修改后必须执行 H5 构建、部署钩子和远端 Playwright 手机视口验收。
