# 护理报告真实样例视觉对齐设计

## 目标

以用户提供的真实护理报告为视觉基准，统一 H5 编辑预览与 Go 后端最终 JPG 的字体、字重、日期、勾选符号、字段标签和长备注排版。最终报告必须在不同手机和浏览器上保持一致，不能依赖客户端字体或截图渲染。

## 基准差异

当前生成图与真实样例存在以下确定差异：

- 当前后端仅使用 `SourceHanSansSC-Regular`，填写内容明显偏细；真实样例中的字段值和备注为粗体。
- 当前日期使用 `YYYY-MM-DD`，真实样例使用不补零的 `YYYY.M.D`。
- 当前勾选符号较细小；真实样例使用更粗、更大的勾，并略微越过方框边缘。
- 当前底图显示“上次护理 / Last care”；真实样例显示“护理内容 / Content of care”。
- 当前备注会按单行和较短字符上限截断；真实样例允许较长粗体备注，并在必要时使用两行。

## 方案

### 字体

- 后端新增并嵌入 `SourceHanSansSC-Bold`，保留 Regular 用于覆盖后的静态标签。
- 主字段值、体重、备注统一使用 Bold 字体。
- 前端预览使用现有中文无衬线字体栈并设置 `font-weight: 700`，字号和布局参数与后端保持一致。
- 不使用重复描画模拟粗体，避免文字边缘发糊。

### 主字段

- 保留当前已校准的横线和中心位置。
- 按真实样例提高姓名、品种、性别、年龄、护理内容、日期和体重的字号。
- 文本过长时先逐级缩小字号，再做省略；短文本保持基准字号。
- 日期输入与接口仍使用 `YYYY-MM-DD`，仅展示和最终成图格式化为 `YYYY.M.D`。

### 护理内容标签

- 不直接修改底图文件，避免模板像素处理引入压缩和边缘问题。
- 后端在旧标签区域绘制白色遮罩，再使用 Regular 字体绘制“护理内容”和“Content of care”。
- 前端预览使用同尺寸白色覆盖层和相同标签文字，确保编辑时所见即所得。

### 勾选符号

- 保留已通过底图像素扫描得到的方框中心坐标。
- 增大折线尺寸和线宽，使勾略微越过方框，匹配真实样例。
- 后端使用固定路径绘制；前端使用固定 CSS 尺寸绘制，不使用字体字符。
- 增加几何测试，约束勾的中心、范围和线宽，防止后续再次漂移。

### 备注排版

- 备注使用 Bold 字体并在横线区域水平居中。
- 优先按基准字号单行展示；超宽时逐级缩小到最小字号。
- 最小字号仍无法容纳时，按可用宽度拆成最多两行，并在相邻检查行之间的备注区域垂直居中。
- 提高备注字符上限，超过两行容量时才在第二行末尾省略。
- 前端预览复用相同的字符宽度估算、最大两行和字号下限规则。

## 数据与接口

- 不修改订单、猫咪或护理记录的数据结构。
- 不修改报告生成接口字段。
- 日期格式变化仅发生在显示层和图片渲染层。
- 报告保存流程、猫咪归属校验和护理记录落库行为保持不变。

## 验证

1. 后端单元测试覆盖 Bold 字体加载、日期格式、标签覆盖、勾选几何和两行备注。
2. 前端源码测试覆盖日期显示、粗体样式、标签覆盖和勾选参数。
3. 生成一张使用真实样例字段和本地猫咪图片的完整 JPG，与真实样例并排检查。
4. 运行 `go test ./...` 和 `pnpm build:h5`。
5. 部署前后端，核对远端二进制哈希、健康检查和静态资源内容。
6. 使用浏览器打开远端页面；若独立 Playwright 会话未登录，至少验证远端页面加载、静态包和公开测试成图。

## 非目标

- 不修改真实订单或客户数据来制造测试报告。
- 不改变护理报告编辑表单的业务字段。
- 不重做整张模板或调整品牌颜色、头像框和页面结构。
